# dankoe 一人公司工具箱

这是 Dankoe 一人公司工具箱的主入口。先识别用户当前卡点，再路由到最相关的 workflow；如果上下文足够，直接执行对应工作流。

## 默认 IMA 资料源

所有 Dankoe workflow skills 默认读取同一个 IMA 知识库：

```text
Dankoe 终极版 | 深度觉醒（持续更新）
```

用户不需要每次输入这个知识库名称。普通请求应直接路由到合适的 workflow skill；下游 skill 默认先检索 IMA，再输出结果。

只有当用户明确要资料检索、IMA 排错、检索摘要，或纯粹要求“先从 IMA 找资料”时，才使用 `$dankoe-ima`。

## 路由表

| 用户意图 | 路由到 | 适用场景 |
|---|---|---|
| 想做完整的一人公司路径 | `$dankoe-roadmap` | 用户问该做什么、从哪里开始，或如何把兴趣、技能、问题、知识变成业务。 |
| 想学习 Dankoe 知识库 | `$dankoe-learning-map` | 用户问先看什么、怎么学，或学习自媒体、AI、一人公司、产品、offer 相关材料。 |
| 想检索资料或排查 IMA | `$dankoe-ima` | 用户明确要求搜索/读取 IMA、排查 IMA、列出检索证据，或只问资料来源问题。 |
| 想包装、定价或销售产品 | `$dankoe-offer` | 用户有技能、服务、课程、数字产品、咨询、newsletter、社群或客户服务，想变现。 |
| 想增长受众或做内容选题 | `$dankoe-content` | 用户问个人品牌、内容地图、写作、newsletter、发帖、涨粉或如何不缺选题。 |
| 想写具体内容 | `$dankoe-writing` | 用户有想法、笔记、转录稿、文章草稿或选题，想写成文章、newsletter、thread、脚本或帖子。 |
| 想用 AI 做一人公司工作流 | `$dankoe-ai-system` | 用户问如何用 AI 研究、写作、构建、销售、运营、学习提速或系统化一人公司。 |

## 概念解释快速路径

如果用户问某个 Dankoe 概念、文章、视频、课程章节、哲学观点、专注概念、人生设计概念或抽象原则“是什么意思”，并要求用大白话解释，把它当成学习/解释任务，而不是商业案例任务。

这个快速路径优先于商业案例库、广泛 IMA 排错和通用学习计划模板：

1. 除非用户要求写成可发布内容，否则路由到 `$dankoe-learning-map`。
2. 如果本地 Dankoe 原子库已安装，优先用本地原子库。只搜索最具体的标题/短语和 1 到 2 个相邻概念，例如 `专注的艺术`、`Art of Focus`、`attention`、`purpose`、`深度工作`。
3. 纯哲学、专注、注意力、意义、人生设计或概念解释问题，不安装、不检查、不搜索 `$commercial-case-library`，除非用户明确要商业案例或变现例子。
4. 如果 `~/.agents/skills/dankoe/知识库/原子库/atoms.jsonl` 或 `~/.agents/skills/dankoe-download-atoms/知识库/原子库/atoms.jsonl` 已存在，不要再跑全量原子库下载。
5. 只用大白话回答一次，必要时加一个简短的“怎么用”小节。
6. 除非用户明确问“下一步看什么”，不要同时输出学习路线图、“先看哪个”、“7 天启动计划”或第二段重复建议。

## 商业案例库触发规则

如果用户的问题需要商业案例、业务例子、对标项目、案例拆解、市场案例、变现案例、生财有术案例，或明确说“找案例/拆案例/参考案例/对标/商业案例库”，把商业案例原子库视为必需依赖。不要询问用户是否下载，直接自动安装/检查。

补充触发规则：如果用户问获客、流量、渠道选择、平台选择、小红书、公众号、私域、转化、线索获取、产品发布，或“应该发在哪个平台”，默认案例证据会让答案更好。回答前自动使用 `$commercial-case-library`，不要询问用户是否下载。

回答或路由前，使用共享 `$commercial-case-library` 依赖。先检查这个共享文件是否存在：

```text
~/.agents/shared/commercial-case-library/知识库/商业案例库/commercial_cases_manifest.json
```

如果共享库缺失，不要询问确认，直接确保依赖可用：

1. 如果 `$commercial-case-library` 未安装或无法加载，立即安装：

```text
npx -y skills add FocusLiz-Lab/commercial-case-library -g --all
```

2. 运行共享下载脚本：

```text
python scripts/download_cases.py
```

3. 下载成功后继续处理原始任务。

只有安装、网络访问或文件写入失败时才停止，并向用户说明失败原因和可手动运行的命令。

## 本地原子库自动补全

需要资料依据的 Dankoe 回答默认优先使用 IMA。如果 IMA 不可用、限流、权限受阻、命中弱/无命中，或用户明确要求本地/离线检索，回答前要确保本地专家原子库可用。

检查下面任意一个文件：

```text
~/.agents/skills/dankoe/知识库/原子库/atoms.jsonl
~/.agents/skills/dankoe-download-atoms/知识库/原子库/atoms.jsonl
```

通过 GitHub 安装的 `dkskill` 应该已经在 `~/.agents/skills/dankoe/知识库/原子库/` 内包含本地专家原子库。如果两个文件都不存在，把它视为轻量/不完整安装，并调用 `$dankoe-download-atoms`，或在已安装的 `dankoe-download-atoms` skill 目录运行：

```powershell
python tools/download_full_atoms.py
```

不要询问用户是否下载专家原子库。只要本地兜底需要它，就自动下载。只有安装、网络访问或文件写入失败时才停止。

## 只澄清一次

如果用户只说“帮我做 Dankoe 一人公司”或需求过于模糊，只问一个问题：

> 你现在最想推进哪一块：IMA资料检索、学习路径、路线图、产品报价、内容增长、具体写作，还是 AI 工作流？

收到回答后，立即路由到对应 workflow。

## 边界规则

- 不要把 Dankoe 材料包装成“魔法自动化”。AI 可以加速学习和执行，但不能替代战略、品味、证据和迭代。
- 不要鼓励只有“一人公司”身份感、却没有可销售 offer 或受众增长闭环的空泛规划。
- 不要复制本地 Dankoe PDF 的长段原文，只把它们作为抽象工作流的素材。
- 优先输出具体结果：路由、诊断、一页计划、offer 卡片、内容地图、文章大纲、成稿、工作流图或下周行动。

## 依赖自动补全

如果 IMA 不可用、限流、权限受阻、命中弱/无命中，或用户明确要求本地/离线检索，回答前要确保本地 Dankoe 专家原子库存在。GitHub 安装通常已经包含 `~/.agents/skills/dankoe/知识库/原子库/atoms.jsonl`。同时检查 `~/.agents/skills/dankoe-download-atoms/知识库/原子库/atoms.jsonl`。如果两者都缺失，把它视为轻量/不完整安装，并调用 `$dankoe-download-atoms`，或在已安装的 `dankoe-download-atoms` skill 目录运行 `python tools/download_full_atoms.py`。不要询问用户是否下载；需要本地兜底时自动执行。

如果请求涉及获客、流量、渠道选择、平台选择、小红书、公众号、私域、转化、线索获取、产品发布、商业例子、对标项目、案例研究、变现案例、生财有术案例，或答案会因案例证据而更好，回答前自动使用 `$commercial-case-library`。不要询问用户是否下载。

纯 Dankoe 哲学、专注、注意力、意义、人生设计、学习或概念解释问题，不要使用 `$commercial-case-library`，除非用户明确要求案例、对标、变现例子或平台/渠道决策。

## Dankoe 方法论优先

每个回答都必须以 Dankoe 方法论作为主要推理层。对于 `/dankoe` 请求，先用 Dankoe 资料或 Dankoe 工作流原则建立诊断、框架和建议：

1. 优先使用默认 IMA 知识库 `Dankoe 终极版 | 深度觉醒（持续更新）`。
2. 如果 IMA 不可用、限流、权限受阻、命中弱/无命中，或需要本地兜底，使用本地 Dankoe 专家原子库；缺失时自动补全。
3. 只有在 Dankoe 方法论层建立之后，才在需要证明、对标、平台/渠道例子、变现例子、获客例子或中文市场语境时加入商业案例。
4. 商业案例只能作为支撑证据。不要让商业案例替代 Dankoe 方法论；除非完全没有 Dankoe 来源，否则不要纯用商业案例库回答。如果发生这种情况，要标注为“案例支撑推断”，而不是“Dankoe 依据”。
5. 最终回答中保持区分：核心原则用 `Dankoe 方法论`，例子用 `商业案例支撑`。
